# 二进制观测交换协议 v1

每帧为魔数 A5 5A、2 字节大端无符号载荷长度、载荷、4 字节大端 CRC32。CRC 覆盖魔数、长度及载荷，算法 zlib.crc32。首版载荷长 26 字节，按小端依次为 uint32 boot_id、uint16 sequence、uint16 channel、uint16 directory_version、int64 UTC 毫秒时间、float64 原始值。sequence 按 65536 回绕，每个 boot/channel 独立；身份需含回绕世代。采集从已知起点开始，不允许推断未知中途回绕次数。

结束标记为 ASCII END!、2 字节大端 JSON 长度和 UTF-8 JSON，counts 键为 boot:channel。重复重发帧不增加 counts；CRC 损坏无法证明内容，应计入缺口说明。单帧上限 4096 字节。目录 /channels/1 给通道映射，校准仍由量衡按事件时间管理。

/frames 正常；?bad=1 中间 CRC 损坏；?cut=1 尾部截断。这里仅有发送样本和格式自检，没有接收解帧器。

运行 python demo_support/source.py --port 8787 可启动回环来源；运行 python demo_support/check.py 检查样本和故障开关。来源仅产生输入，不调用业务导入。

## 量衡侧直接采集入口

解帧与采集由业务包 metrology.ingress 实现，不再需要先拆成 JSON：

- binary.py：增量 FrameParser，按字节重组任意 HTTP 分块。魔数出现在载荷或噪声中不会误判；CRC 失败产生 crc_failure 事件并从下一魔数重新同步；任何无法解释的字节区间都产生带偏移、长度与十六进制预览的 resync_gap 事件，不会静默吞字节。缓冲超过有界上限时同样以 resync_gap 释放。
- directories.py：通道目录按 version 注册并带 valid_from/valid_until 半开有效时段，映射按帧的采样时间选择；未知版本保持 deferred 状态，禁止套用当前校准凑值。
- gateway.py：GatewayCollector 管理可取消会话。身份为 boot_id、通道、序号加显式回绕世代；同一帧重发记 retransmitted，同序异载荷记 conflict 并进入隔离行；流尾 END counts 与实到帧逐 boot:channel 对账，缺帧进入 summary.missing；正常结束（complete）、无有效尾标（truncated）、尾标 JSON 损坏（trailer_corrupt）、取消（cancelled）是不同终态。
- transport.py：仅允许显式 http 主机端口的回环采集，按有界块读取并在每次读取前检查取消回调。
- reprocess_session 在目录版本补齐后重解析 deferred 帧；reprocess_frame 提供单帧隔离重处理入口。

运行 python -I demo_support/drill_gateway.py 执行综合演练：合法帧任意切块、CRC 损坏、boot 重启、65535→0 回绕、重发与同序异载荷、未知目录版本后补、流尾缺帧对账，并核对最终观测、缺口与按采样时间选择的校准依据。
